# 第二轮优化：通知状态有界批量回写（2026-10-24）

本轮已实现通知成功回执的有界批量回写、事务阶段观测、通知状态保护和短周期补偿，并完成真实交易回归与六轮对照。通知状态更新调用按团数归一化后减少 78.89%，但本机测试未验证到整体性能提升，因此批处理默认关闭，保留显式开关用于后续复测。

## 代码行为

- 新增 INotifyTaskStatusWriter 端口及 NotifyTaskStatusWriter 实现；仅接收通知发送成功后的回执。默认 trade.notify.batch.enabled=false，显式设为 true 才启用。
- 待写队列与正在写入的任务合计最多 1024 个唯一 teamId，同一任务合并重复回执；每批最多 32 个任务，默认每 100 ms 触发检查，达到批量阈值时主动触发。调度、排队和写库会增加实际耗时，100 ms 不是写回完成的上界。
- 一个批次使用一条 UPDATE 完成多个任务状态更新；队列满时同步写回形成背压。批量失败后释放内存占用，已落库的待通知任务继续由补偿任务处理。应用正常关闭时尝试排空队列。
- 单条与批量成功回写均有幂等条件；失败/重试更新只允许修改待处理状态，已成功任务不会被旧失败回调降级。
- 通知补偿由原每日一次改为默认每 10 秒一次，可用 trade.notify.retry-cron 配置。已在本实例等待回写的任务会跳过重复发送；其他竞争窗口仍采用至少一次投递，由条件更新及消费者幂等处理重复。
- 修复普通发送异常错误设置工作线程中断标记的问题，发送失败进入已有失败/重试流程。真正的 InterruptedException 仍保留中断标记。
- TradeTransactions 使用 REQUIRED 事务模板，保留下单、结算各自原有写入原子性和默认 500 秒事务超时，分段记录开始、业务执行、事务完成和总耗时。Kafka 发送继续发生在结算事务返回后。
- 修正 application-dev.yml 的 Hikari/type 层级，使用 spring.datasource.hikari。开发配置的池大小为 25、最小空闲 15；本次两组均由命令行显式固定为最大 10、最小空闲 2。

## 验证

- 最终七模块构建成功，22 项 Java 测试通过；覆盖并发回执合并、队列满回退、正在写入时的容量与去重、批量失败后重试、低流量定时触发、关闭排空、开关行为、真实 Spring 缺省和覆盖配置、事务提交/回滚/提交失败、队列状态计数及普通异常中断标记。
- 5 项 Python 保护测试与脚本编译通过，覆盖专用容器归属、固定对照库、低内存保护、相同构建/索引的单项对照、每轮日历种子恢复。
- 两组各通过 8 类真实回归：原有六类并发交易场景，加上直接执行实际 mapper SQL 的成功状态保护，以及模拟消息已发出但 ACK 状态未记录的补偿恢复。
- 补偿模拟通过将专用测试中已确认通知的状态恢复为待处理来重现持久化状态，并观察定时任务再次发送及消费者幂等处理；两组分别在约 7.172 秒和 2.782 秒恢复。该用例没有实际杀死生产进程。
- 六轮负载共完成 13,152 个已支付订单、6,576 个完整团，26,304 次业务 HTTP 请求均成功；无重复订单、库存差异、漏成团、失败通知或最终消费标记缺失。计数包含预热和收尾，不含独立回归及冒烟。
- 独立重读六份 JTL 重算 TPS/P95/P99，并与订单、库存及 Kafka 核验交叉验证，结果一致。

## 对照口径

运行时间：2026-10-24 18:58:42—19:10:32（Asia/Shanghai）。两组使用同一构建、相同两条订单索引和相同数据库持久性配置，仅切换 trade.notify.batch.enabled。基线为关闭，优化组为开启；这不是与上一轮旧构建的比较。

按“关、开、开、关、关、开”交替运行，每轮 50 虚拟用户、60 秒、前 15 秒预热，固定 45 秒计量。每阶段恢复固定专用对照库及日历库存种子、清空已备份的专用测试 Redis、使用新 Kafka 主题。

业务模型为单热点票种、二人团的新团创建及参团：下单、测试支付回调结算、再下单、再结算。订单、Redis 库存和 Kafka 真实运行，未调用外部支付或景区出票服务。完整流程时延不包含异步消费等待；消息及状态最终完成由独立核验检查。

JDK 17，应用最大堆 320 MiB，JMeter 最大堆 128 MiB，Tomcat 最大 20 工作线程，Hikari 最大 10 连接。MySQL innodb_flush_log_at_trx_commit=1、sync_binlog=1，buffer pool=64 MiB。

各 TPS/P95/P99 按请求或流程开始时间落入固定计量窗口的成功样本统计，最终数值取各组三轮中位数。资源采样和新增 SQL/应用指标涵盖预热、负载及核验，不等同于固定 45 秒窗口。
